How to create a connector

  2. Press + Create to start configuring the channel.
  3. In the Parameters tab, assign a new private key with the option marked in the image:

  4. After that, the assigned Channel private key will appear on screen. You will need the Connector ID code and this Channel private key to continue with your e-commerce configuration.
  5. To save the channel, click "Continue and Save" and then "Complete" in the top-right corner of the screen.
  6. You must finish the channel configuration before setting it up in the WooCommerce plugin.
How to do a first synchronization
  1. Add the connector in WooCommerce: Once your Sales Layer channel is fully configured with field mappings, go to Connectors and click Add connector. Enter the Connector ID and Channel private key from Sales Layer. The plugin will validate your credentials and connect to your Sales Layer account.
  2. Enable logging before testing: Before running any synchronization, you must enable debug logging so you can review what happens. Go to General Parameters and ensure the Debug Level is set to at least 1 (or higher for more detail). Logging is essential for diagnosing issues.
  3. Test in a staging environment: Never test synchronization on a production site. If you don't have a staging environment, create a backup of your WooCommerce database first. Synchronization can create many items, and you need a safe space to validate your configuration before going live.
  4. [Optional] Configure Multisite and Multilanguage settings (if enabled in your installation):
    • Multisite: If you have a WordPress multisite installation and want to synchronize products across multiple sites, you can configure which sites should receive the synchronized items. Go to Connectors, select your connector, and in the settings panel you will find the multisite configuration section where you can select which blogs (sites) should be active for this connector.

    • Multilanguage: If you are using a multilanguage plugin (Polylang) and want to synchronize items in multiple languages, you need to configure the language mappings in the connector settings. This ensures that each product variant is correctly synchronized to its corresponding language. The mapping section will show your available languages from Sales Layer and allow you to assign them to the languages configured in your WooCommerce store.

      • ⚠️ Important: If you have already synchronized data using a version prior to 2.6.1 (without multilanguage support), you will have duplicate items after enabling multilanguage features. To resolve this, use the Migrate Legacy Items tool in the Tools panel. This will assign language metadata to your existing items and prevent duplication.

  5. Create a small test batch: In Sales Layer, filter and prepare a small set of items to test (e.g., 5-10 products with their categories and variants). To synchronize only these items:
    • In Sales Layer, mark only your test items as visible.
    • Create a tag or filter in Sales Layer to identify them (e.g., "test_sync").
    • Go to your Sales Layer WooCommerce channel's Output data tab and add a filter for this tag in the Products section.
    • Include related items: Make sure to include the parent categories and variants for your test products, otherwise the sync may fail with "parent not found" errors.
  6. Run the first test synchronization: Go to Connectors, click "Synchronize!" on your connector. Do not set up automated synchronization yet. Manual synchronization allows you to control when items are processed and review results immediately.
  7. Review the synchronization results: After the synchronization completes (check the progress counters in the grid), go to Tools and click Download SL Logs. Extract the logs and search for:
    • "Error" entries — these indicate failures. Note the exact error messages.
    • "initialized" messages — confirm that categories, products, and variants were processed.
    • Blog_id and Language context — verify the correct sites and languages were targeted.
  8. Fix errors and repeat: If you find errors in the logs:
    • Common issues: missing required fields, invalid category relationships, duplicate product SKUs.
    • Go back to your Sales Layer channel and fix the data or field mappings.
    • Remove the test items from your WooCommerce store (or mark them as draft).
    • Run the synchronization again to re-test. Repeat until no errors appear.
  9. Expand the test batch: Once your small test batch syncs successfully, gradually increase the number of items:
    • Test with 50 items, then 200, then 500.
    • Monitor each run for new errors.
    • This incremental approach helps identify configuration issues before syncing thousands of items.
  10. Deploy to production: When you're confident the configuration is correct:
    • Remove the test tag/filter from your Sales Layer channel configuration.
    • Log in to your production WooCommerce site and add your connector using the same credentials.
    • Run the first production synchronization with the full item set.
    • Monitor logs closely during and after the sync.
    • Once complete, you can enable automated synchronization if desired (set via Sales Layer channel settings).
My connector appears to be stuck or not synchronizing

Normal behavior during synchronization: When a connector is processing data, you will see a progress indicator in the grid view. While there are pending items to process, the item counts will update automatically:

The synchronization runs in the background via a scheduled task (WP-Cron). Depending on your server configuration and the volume of items, synchronization can take anywhere from a few minutes to several hours.

Troubleshooting steps:

  1. Check the logs: Download the SL logs from Tools and review them for error messages. Error logs will show exactly where the synchronization failed.
  2. Check your server's WP-Cron: Some hosting providers disable WordPress scheduled tasks. Contact your hosting provider to ensure WP-Cron is enabled.
  3. Review server error logs: If WP-Cron is working but items aren't processing, check your server's PHP error logs for timeout or memory errors. Note any error messages.
  4. Contact Sales Layer Support: If none of the above resolve the issue, provide the error logs and describe what you've verified. This will help diagnose the root cause.

Multilanguage Setup (Polylang)

Setting up Polylang for multilanguage synchronization

Polylang is a lightweight multilanguage plugin that allows Sales Layer WooCommerce to synchronize products in multiple languages. Here's how to set it up:

  1. Install and activate Polylang: Download the Polylang plugin from the WordPress plugin directory (free version is sufficient for e-commerce use). Activate it from your Plugins menu.
  2. Configure your site's languages: Go to Languages → Languages in the WordPress admin menu. You will see a list of available languages to add:

    • Click "Add new language" for each language your store will use.
    • Language code: This must match exactly the Sales Layer language codes. For example, if Sales Layer has 'es', 'en', and 'de', add those codes in Polylang. Check your Sales Layer connector to see which languages are available.
    • Locale: Auto-populated based on your language selection. This controls date/number formatting.
    • Default language: Set one language as default (usually your primary/main market language).
  3. Enable language management for Products and Categories: Go to Languages → Settings and scroll down to find the content type management section. This is where you tell Polylang which WordPress content types should be multilingual:

    • Ensure "Products" (Posts) is checked — this allows Polylang to manage language variants of WooCommerce products.
    • Ensure "Product Categories" (Terms) is checked — this allows Polylang to manage language variants of product categories.
    • If unchecked, Polylang will not track language metadata for these content types, and multilanguage synchronization will fail.
  4. Map Sales Layer languages to Polylang languages: Once Polylang is fully configured, go to your Sales Layer connector in Connectors. Click Settings to open the Site & Language Configuration modal. The modal will show:
    • Available Sales Layer languages at the top (in a badge list).
    • A dropdown for each Polylang language you created, allowing you to map each WP language to a Sales Layer language.
    Complete the language mapping and save.
  5. Verify the configuration: After mapping, run a test synchronization with a few products (see "How to do a first synchronization"). Monitor the logs to ensure products are being created with correct language metadata.
Why Polylang is sufficient (you don't need Polylang for WooCommerce)

You may see "Polylang for WooCommerce" in the plugin directory. You do not need to install it. The Sales Layer WooCommerce plugin handles all WooCommerce-specific multilanguage requirements natively. Polylang (free version) alone is sufficient. Here's why:

  • Stock management is per-item: Unlike some multilanguage approaches that share stock across variants, Sales Layer synchronizes stock separately for each language variant. This means inventory is replicated and managed independently, ensuring accurate stock levels across all language versions without requiring additional WooCommerce extensions.
  • Product data is language-aware: The plugin automatically detects and filters product fields (title, description, attributes, custom fields, etc.) based on the language suffix from Sales Layer. Each variant receives only the data for its language, eliminating data confusion.
  • Variants are properly linked: Polylang's translation groups automatically link all language variants of the same product as a cohesive translation set. The Sales Layer plugin leverages this during synchronization to keep variants grouped together.
  • Polylang handles language infrastructure only: Polylang manages:
    • Language configuration and assignment (which content uses which language)
    • URL structure and locale handling
    • WordPress admin language switcher

    It does not handle synchronization, data mapping, or WooCommerce-specific logic — that's where Sales Layer comes in.

  • Reduced complexity: Avoiding additional plugins reduces maintenance overhead, potential conflicts, and licensing costs. Polylang (free) is lightweight and well-maintained.

Summary: Polylang (free) provides the language layer. Sales Layer WooCommerce provides the e-commerce sync layer. Together, they form a complete multilanguage e-commerce solution at no additional cost.

Multisite Setup

Configuring the plugin for WordPress Multisite

WordPress Multisite allows you to manage multiple WooCommerce sites (blogs) under a single WordPress installation and database. The Sales Layer plugin supports multisite synchronization, enabling you to distribute products from a single Sales Layer connector across multiple sites simultaneously.

  1. Network Activation is Required (Critical Step): The Sales Layer WooCommerce plugin must be activated at the network level, not individually on each site. This enables the plugin to coordinate synchronization across all sites in the network.

    ⚠️ Critical: If you activate the plugin on individual sites instead of the network, multisite features will not work. Go to My Sites → Network Admin → Plugins and activate the Sales Layer WooCommerce plugin at the network level only. Do not activate it on individual sites.

  2. What network activation enables: Once network-activated, the plugin will automatically:
    • Create network-level settings accessible from the main WordPress dashboard.
    • Register the Connectors menu at the network level (visible when logged in as network admin).
    • Allow configuration of connectors that can target any site within the network.
    • Enable intelligent per-site and per-language routing during synchronization.
  3. Configure which sites should receive items: Go to Connectors and select your connector. Click Settings to open the Site & Language Configuration modal. Here you can:
    • See a list of all sites in your network (with checkmarks showing which have WooCommerce installed).
    • Toggle the "Activate" checkbox to select which sites should receive items from this connector.
    • Each site can receive items independently — you don't have to include all sites.
  4. Multisite + Multilanguage (optional): If you're running multilanguage sites within your multisite network using Polylang:
    • In the Site & Language Configuration modal, each site will show its configured languages.
    • You can map Sales Layer languages to each site's languages independently.
    • Example: Site 1 (Spain) receives 'es', Site 2 (Germany) receives 'de'.
  5. How synchronization works: When you click "Synchronize!" on a connector:
    • The plugin fetches items from Sales Layer.
    • For each item and each selected site, it creates a queue entry.
    • The background task processes each entry, automatically switching to the correct site context before creating/updating items.
    • Each site receives only the products and variants you configured for it.

Logs & Debugging

How to download and review logs

Logs are essential for debugging synchronization issues. The Sales Layer plugin generates detailed logs for every synchronization attempt, including success messages and error details.

To download logs:

  1. Go to Tools → Download SL Logs
  2. A zip file containing all plugin logs will be generated and downloaded to your computer.
  3. Extract the zip and review the log files. The most recent synchronization will be in the newest files.

What to look for in logs:

  • "initialized" messages — indicate that a product/category/variant sync has started. Look for these to confirm items are being processed.
  • "Error" messages — show what went wrong. Include exact error messages when contacting support.
  • "Blog_id: X - Lang: XX" context — shows which site and language variant was being processed when an error occurred (useful in multisite/multilang setups).
  • Timestamps — help you correlate log entries with when you initiated the synchronization and understand how long processing took.
Where logs are stored and enabling debug mode

Default storage location: Logs are stored in your WordPress installation's WooCommerce logs folder: /wp-content/plugins/woocommerce/logs/

Enabling higher debug verbosity: By default, the plugin logs synchronization events. To increase logging detail and capture more information:

  1. Go to General Parameters
  2. Set the Debug Level to a higher value:
    • Level 0: Minimal logging (only errors)
    • Level 1: Standard logging (recommended)
    • Level 2: Verbose logging (more detail)
    • Level 3: Maximum verbosity (very detailed, generates large logs)
  3. Run your synchronization again. More detailed debug information will be logged.
  4. Download and review the logs to find additional context about what's happening.

⚠️ Note: Higher debug levels generate significantly larger log files. In production environments with frequent synchronizations, remember to disable debug mode (set to 0) or clean logs periodically to avoid filling disk space.

Plugin Tools

Download SL Logs

Generates a compressed zip file containing all Sales Layer synchronization logs currently stored on your server, then automatically downloads it to your computer.

What it includes: All plugin logs from every synchronization run, including success messages, error details, and timestamps.

When to use it:

  • When you need to review synchronization history and identify issues.
  • Before contacting Support — always provide downloaded logs with your issue description.
  • To archive logs before clearing them (see "Remove SL Logs" below).
  • To analyze performance and synchronization patterns over time.

How to use it: Click the button, wait a few seconds, and the zip file will download. Extract it on your computer and open the log files in any text editor.

Remove SL Logs

Permanently deletes all Sales Layer logs from your server. This frees up disk space.

⚠️ Warning: This action cannot be undone. Deleted logs are gone forever.

When to use it:

  • After you've downloaded and archived logs (see "Download SL Logs" above).
  • As part of regular maintenance on high-volume production environments.

⚠️ Best practice: Always download logs before removing them. If synchronization issues occur after deletion, you won't have historical logs to reference for debugging.

Delete SL items pending to process

Removes all items currently queued in the synchronization table that haven't been processed yet. This clears the internal queue completely.

What it does:

  • Finds all queue entries for categories, products, and variants waiting to be synchronized.
  • Deletes them from the queue table immediately.
  • Does NOT delete already-synchronized items from your WooCommerce store — only removes pending queue entries.

When to use it:

  • When a synchronization is stuck and not making progress (items remain in "pending" state for hours).
  • When you've identified errors in your configuration and want to clear the queue before resyncing.

⚠️ Warning: Once you delete pending items, they must be requeued by running synchronization again. Any partial work is lost.

How to recover: After clearing the queue and modifying the deleted pending items again, run the synchronization again. Sales Layer will re-fetch the items and requeue them.

Delete SL credentials

Removes all Sales Layer metadata (SL IDs and tracking information) from existing products, categories, and variants in your WooCommerce store. This breaks the link between your store and Sales Layer.

What metadata is deleted:

  • _saleslayerid — the Sales Layer product ID
  • _saleslayercompid — the Sales Layer company ID
  • _saleslayerformatid — the Sales Layer variant/format ID
  • saleslayerid (terms) — Sales Layer category ID
  • saleslayercompid (terms) — Sales Layer company ID
  • Other Sales Layer tracking fields

Impact: Without this metadata, your WooCommerce store can no longer recognize which items came from Sales Layer. Future synchronizations will treat these items as new and links them if their keys matches.

When to use it:

  • You are migrating to a different Sales Layer connector.
  • You want to "reset" your store and start fresh synchronization.

🔴 Critical Warning: This is a destructive operation. The link between your items and Sales Layer might not be easily restored. Before proceeding:

  1. Test in staging first if you're unsure.
Clean orphaned multiconn

Removes "orphaned" multiconn records from the database. Multiconn records are internal references that track which connectors have synchronized which items to which sites.

What is a multiconn record: In a multisite setup, the plugin maintains a reference table (multiconn) with one row per (connector, item, site) combination. This allows the plugin to:

  • Track which connectors have synchronized a specific item to a specific site.
  • Safely delete items only when NO remaining connectors reference them on that site.
  • Prevent premature deletion when multiple connectors share the same product IDs.

When records become orphaned: Records become orphaned in two scenarios:

  1. Deactivated sites: If you remove a site from a connector's Site & Language Configuration, the multiconn records for that connector-site pair are no longer needed.
  2. Deleted connectors: If a connector is completely removed from the system, its multiconn records are no longer referenced by any active connector.

What this tool does:

  • For each configured connector, identifies multiconn records pointing to sites that are NOT in its current active targets.
  • Deletes those orphaned records per-connector and per-site.
  • Returns the total number of rows deleted.

When to use it:

  • After removing sites from a connector's Site & Language Configuration to clean up leftover database entries.
  • As part of regular database maintenance in production multisite environments.
  • Optional — not required for normal operation, but helps keep the database clean.

Safety: This tool is safe. It only removes records for deactivated site/connector combinations and will not affect items on currently active sites or impact item deletion logic.

Migrate Legacy Items

This tool migrates items that were synchronized before multilanguage support was enabled in the plugin. It is useful when you are transitioning from a single-language setup to a multilanguage installation (with Polylang).

What does it do:

  • Identifies all products, categories, and variants that do not yet have language metadata assigned.
  • Assigns the primary language of your site (configured in Polylang settings) to these items.
  • If Polylang is active, creates language translation links so that variants are properly grouped by language.

When to use it:

  • After activating Polylang on a site that already has synchronized products.
  • When you are setting up multilanguage synchronization for the first time.
  • To ensure existing items are compatible with the new multilanguage queuing system.

How to use it: Click the Migrate Legacy Items button in the Tools panel. The process will run in the background and display a summary of how many items were migrated (categories, products, and variants).

Note: This tool is idempotent, meaning it can be run multiple times without causing issues. Items that have already been migrated will not be processed again.
